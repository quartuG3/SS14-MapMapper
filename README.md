# SS14 Shuttle Mapper

Локальный веб-редактор шаттлов для сборок на базе Frontier (Mono / LuaM). Читает прототипы, текстуры и
карты прямо из репозитория, путь к которому задан в `conf.toml`, и сохраняет грид в формате карт движка
(format 7). Игру для этого запускать не нужно.

## Запуск

Нужен Python 3.11+.

Проще всего дважды кликнуть по `run_mapper.bat`. Он проверяет, что Python и пакеты установлены
(если пакетов нет, предлагает поставить их из `requirements.txt`), создаёт `conf.toml` из
`conf.example.toml` и открывает его в блокноте, а потом проверяет конфиг: существует ли путь,
есть ли в нём `Resources/Prototypes`, корректен ли порт. Сервер стартует, только если все проверки прошли.

Вручную:

```
pip install -r requirements.txt
copy conf.example.toml conf.toml   # и указать path
python -m ss14map.check            # необязательная проверка окружения
python mapper.py                   # откроет http://localhost:8714
```

Первый запуск индексирует ~5000 файлов прототипов (около 45 с). Индекс кэшируется в `.cache/`
и пересобирается сам, когда прототипы в репозитории меняются.

`conf.toml` локальный и в git не попадает (шаблон: `conf.example.toml`):

```
path=C:\Users\...\Monolith-DS   # корень репозитория (обязательно)
# port = 8714
# locale = "ru-RU"               # вторая локаль для поиска по названиям
```

## Сохранение

По умолчанию «Сохранить» отдаёт готовый `.yml` браузеру, и он попадает в «Загрузки». Путь в диалоге
задаёт имя файла. Чтобы записать файл прямо по этому пути, включите в диалоге «Записать файл по этому пути».
Путь от `Resources/` пишет в репозиторий, путь `user/<файл>.yml` пишет в «Мои шаттлы» (кнопка «→ мои шаттлы»).
Выбор запоминается.

## Открытие

Диалог «Открыть» (Ctrl+O) состоит из двух списков.

- **Мои шаттлы** — папка `shuttles/` маппера (в git не попадает). Свои `.yml` загружаются сюда перетаскиванием
  в диалог или кнопкой выбора файлов, можно несколько сразу. Файл проверяется (должен читаться как карта SS14),
  при совпадении имени маппер спросит, заменить ли. Один загруженный файл сразу открывается (флажок).
  Отсюда же файлы удаляются.
- **Билд** — все файлы карт из `Resources/Maps` и `Resources/SharedMaps`: гриды (шаттлы, POI), целые карты
  (станции, категория `Map`) и файлы старого формата 6. Фильтр по пути и по типу.

В файле с несколькими гридами редактируется самый крупный, другой выбирается списком в заголовке окна.
Карта, другие гриды и всё, что к ним относится, сохраняются без изменений.

## Что умеет

| Задача | Как |
|---|---|
| Тайлы | кисть `B` (размер `[` `]`, случайный вариант), линия по Shift, прямоугольник по Ctrl, ПКМ стирает. `R` / `Shift+R` поворачивает тайл: фигурные (клинья, углы, `HalfTilt`) переключаются на тайл нужной ориентации по геометрии, тайлы с `allowRotationMirror` получают поворот |
| Прототипы | `E`: поиск по id, английскому и русскому названию, категории; поворот `R`; привязка позиции (центр тайла, ½, ¼, ⅛, 1 px), Shift ставит свободно; опция «дубликаты» для нескольких одинаковых прототипов в одной точке; замена стен (PlacementReplacement); Ctrl+тянуть заполняет прямоугольник, Ctrl+Shift рисует его контур. Инспектором `V` сущность можно тащить или сдвигать стрелками: 1 px, с Shift ¼ тайла, с Ctrl на тайл |
| Декали | `D`: цвет и прозрачность, поворот, z-index, cleanable, привязка к тайлу |
| Зеркало | кнопки `⇋ X` / `⇵ Y` и ⚙ «Настройка симметрии». Ось перетаскивается за фиолетовый маркер на линейке. Все кисти, трубы, кабели и вставка рисуют симметрично. Поворот пересчитывается, пары Left↔Right и `*Flipped` меняются местами, суффиксы NE↔NW/E↔W тоже, фитинги труб подбираются заново, диагональные стены учитываются. Для остального есть пресеты отражений (см. ниже) |
| Линейки | линейки по краям холста. Потяните с линейки, чтобы создать голубую направляющую; её можно перетаскивать любым инструментом. Удалить: ПКМ по линии, перенос обратно на линейку или клик по ⌗ в углу (удаляет все). Инструмент `L` меряет длину и площадь |
| Выделение | `M` (прямоугольник, Shift добавляет, Alt вычитает) и `W` (волшебная палочка, с Ctrl по прототипу). Копировать, вырезать и вставить можно с поворотом и отражением (R/H/J), выделение перетаскивается мышью. Ещё есть: повернуть или отразить на месте, залить, контур, «оболочка» (стены снаружи с подложкой Plating), зеркальная копия, сохранение как префаб |
| Заливка | `G`: заливает связную область тайлом, прототипом или декалью и не проходит сквозь стены |
| Проводка | режим `2` или `C`. Панель быстрого выбора APC, SMES, подстанций, терминалов и генераторов. Кабели кабели HV/MV/LV тянутся мышью, состояния спрайтов соединяются автоматически, сеть под курсором подсвечивается |
| Атмос | режим `3` или `P`. Панель быстрого выбора вентиляций, скрубберов, насосов, клапанов, портов, смесителей, фильтров, термомашин, датчиков и канистр; устройства ставятся с текущим слоем и цветом. Трубы трубы прокладываются с автоподбором Half/Straight/Bend/T/Fourway и правильным `rot`. Поддерживаются слои Primary/Secondary/Tertiary (включая прототипы `*Alt1/Alt2`), пресеты цветов, подсветка сети, открытые концы, оверлей утечек. При сохранении можно пересоздать `GridAtmosphere` (аналог `fixgridatmos`, с учётом маркеров AtmosFix*) |
| Утилизация | режим `4` или `U`. Утилизационные трубы тянутся мышью: конец становится `DisposalTrunk`, дальше прямые, изгибы и развилки с правильным `rot` (крестовин у утилизации нет, такие соединения пропускаются). Тип новых развилок выбирается в панели: развилка (`DisposalJunction`/`Flipped`/`YJunction`), маршрутизатор (`DisposalRouter`) или сигнальный (`DisposalSignalRouter`). Над трубой `R` / `Shift+R` меняет выход развилки, `T` меняет тип (развилка → маршрутизатор → сигнальный, прямая ↔ сортировщик `DisposalTagger`). При перерисовке тип и выход трубы сохраняются, если подходят. Панель быстрого выбора: блоки утилизации и почты, все подтипы труб, туалеты. Сеть под курсором подсвечивается, открытые концы отмечены оранжевым |
| Рандом | наборы элементов с весами (Ctrl+клик в палитре добавляет в набор), кисть `N` с плотностью, «Рассыпать» по выделению, случайные варианты тайлов и повороты, сид для воспроизводимости, готовые пресеты |
| Экспорт PNG | 8–64 px на тайл, фон прозрачный, чёрный или космос. Подпол прячется под полом, как в игре. Есть пресет превью для Shipyard |

### Дополнительно

- **Сканер масс** (кнопка «Сканер»): шаттл так, как его показывает консоль в игре. Рисуются контур грида (с метками `RadarEdgeMarker*`), кольца дальности, азимутная шкала, доки с названиями (`Docking.name`, локализация `dock-label-*`) и сигнатуры `RadarBlip` / `ToggleableSignature` с цветами и формами из прототипов сборки (консоли, ДАМ, двигатели, орудия…). Щит включается отдельно, даже если генератора на шаттле нет: это овал вокруг грида с отступом 50, цвет берётся у генератора. Настраиваются центр (консоль или центр грида), радиус (колесо мыши над сканером), цвета контура, фона и щита. Результат сохраняется в PNG. IFF не рисуется. Кнопка «📌 Закрепить» превращает сканер в мини-окно поверх редактора, как превью. Окно перетаскивается за заголовок, размер меняется за правый нижний угол. ⚙ разворачивает настройки, ⤢ открывает большой сканер. Окно обновляется вживую при правках, пунктиром на нём показана видимая область редактора, клик по сканеру переносит туда вид. Положение и размер окна запоминаются.
- **Проверка шаттла** находит отсутствующие гравген, консоль, двигатели, гироскоп, APC, питание, спавн, док и вентиляцию. Ещё проверяет APC и подстанции без нужных кабелей, неизвестные прототипы, дубликаты, объекты в космосе, открытые концы труб и утечки атмосферы. По клику на пункт вид переходит к проблеме.
- **Сводка**: размер, оценка цены по StaticPrice, потребление и генерация энергии, тяга двигателей по направлениям, статистика прототипов и тайлов.
- **Вессел**: генератор прототипа `type: vessel` и `gameMap` для Shipyard. Данные подтягиваются из существующего прототипа, если он указывает на эту карту. Готовый текст можно записать в `Resources/Prototypes/...`.
- **Поиск и замена** тайла, прототипа или декали по всей карте или в выделении.
- **Префабы** хранятся в `prefabs/` и доступны в любом шаттле.
- **Свои палитры** (вкладка «Палитра» → «★ Свои»): списки тайлов, прототипов и декалей, в одной палитре можно смешивать все три вида. Shift+клик по элементу каталога (или ☆ в строке информации) добавляет его в активную палитру и убирает из неё; «+ из выделения» добавляет всё, что лежит в выделенной области карты. Внутри палитры ПКМ убирает элемент, перетаскивание меняет порядок. Каждая палитра хранится файлом в `palettes/` (каталог в git не попадает); её можно скачать `.json` (⬇), скачать все одним файлом (⬇ все) и импортировать обратно (⬆).
- **Пресеты отражений** (⚙ → «Пресет отражений»): группы из четырёх клеток — исходный тайл/прототип/декаль (чёрная рамка) и его отражения по X, по Y и по обеим осям (между ними фиолетовые оси). Пока группа включена, любой её элемент при зеркалировании заменяется на соответствующую клетку; у клетки можно задать поворот. Нужно для тайлов, которые встроенные правила не узнают по имени, например `LatticeHalfTilt…Lower/Upper`: готовый пресет для них лежит в каталоге.
- **Пресеты в файлах.** Пресеты симметрии и наборы рандома можно скачать `.json` в «Загрузки», загрузить из файла через браузер или сохранить в каталог маппера и загрузить оттуда: `presets/symmetry/` и `presets/random/`.
- **Миграции**: `migration.yml`, `nf_migration.yml` и `mono_migration.yml` применяются при открытии.
- Инспектор правит компоненты сущности как YAML.

### Тексты: бумага, названия, описания

- **Редактор бумаги** (инспектор → «📝 Текст и печати бумаги», у вложенных бумаг кнопка 📝 в списке контейнера):
  текст с BB-кодами слева, справа лист так, как его показывает игра: фон и шрифт сборки (`PaperVisuals`, NotoSans),
  заголовки, цвета, печати. Панель вставляет теги, которые бумага отображает (`bold`, `italic`, `bolditalic`, `uline`,
  `cut`, `head=1..3`, `small=1..6`, `color`, `mono`, `bullet/`, `conf=1..10`, `shift`); прочие теги подсвечиваются как
  неотображаемые. Ctrl+B / I / U — теги, Ctrl+Enter — применить. «Шаблон…» подставляет текст любой бумаги-прототипа
  с готовым текстом (бланки, памятки), «Текст прототипа» возвращает текст по умолчанию; показан лимит `contentSize`.
- **Печати.** Любая резиновая печать сборки (цвет и текст из `Stamp` прототипа, названия из локали
  `stamp-component-stamped-name-*`) или своя: произвольный текст и цвет, тип «печать» (с рамкой) или «подпись»
  (без рамки, цвета ручек и мелков сборки в один клик). Свои печати можно запомнить (★), список хранится в браузере.
  Печати переупорядочиваются и снимаются, цвет меняется. Отметка на спрайте бумаги (`stampState`) выбирается из
  состояний `paper_stamp-*` её RSI; первая печать ставит её сама, как в игре.
- **Названия и описания** (`MetaData.name` / `desc`): поля в инспекторе для выбранной сущности и окно «Названия» (F2)
  со всеми сущностями грида, включая лежащие в контейнерах: поиск, фильтры «только изменённые», «только предметы»,
  «только бумаги», правка прямо в таблице, применение одной правкой (Ctrl+Z). Пустое поле — текст прототипа
  (виден серым, берётся из локали сборки).
- Undo/redo (300 шагов), автосохранение раз в минуту в `.autosave/`, слои видимости, границы чанков.

### Структуры, связи, контейнеры

- **Подложка тайла.** При размещении прототипа на пустом месте под него автоматически кладётся тайл (по умолчанию Plating, настраивается в панели инструмента «Прототипы»).
- **Замена структур.** Опция «заменять структуры»: новая стена/окно/машина удаляет другие структуры в тайле. Без неё редактор предупреждает о нескольких структурах в одном тайле; то же проверяет «Проверка шаттла». Допустимые пары (окно на решётке, пожарный шлюз в проёме, катвок, перила, ставни и т.п.) не считаются ошибкой.
- **Все прототипы в тайле.** Инспектор (`V`): если в тайле несколько сущностей, появляется список для выбора (ПКМ — всегда список). Во вкладке «Инспектор» есть список всех сущностей тайла с выбором и удалением.
- **Связи (`K`).** Режим «Сеть устройств»: клик по воздушной или пожарной сигнализации, затем по вентиляциям, скрубберам, датчикам, пожарным шлюзам — устройство добавляется или убирается (`DeviceList` у сигнализации и `DeviceNetwork.deviceLists` у устройства). Кнопка «Автосвязь комнаты» подключает все подходящие устройства комнаты перед сигнализацией. Режим «Сигналы»: клик по источнику (кнопка, рычаг, датчик), затем по приёмнику — матрица портов с парами по умолчанию (`defaultLinks`), запись в `DeviceLinkSource.linkedPorts`. Слой «Связи устройств» рисует все связи на карте. «Проверка шаттла» сообщает об атмос-устройствах и пожарных шлюзах вне сетей.
- **Содержимое контейнеров.** В инспекторе: список предметов в каждом контейнере (`entity_storage`, `storagebase`, слоты), добавление по прототипу с количеством, удаление, правка компонентов вложенной сущности в YAML, создание контейнера.
- **Подпол при экспорте.** Как в игре: под обычным полом трубы и кабели скрыты, на тайлах с `isSubfloor` видны. У атмос-устройств под полом остаются видимыми слои из `SubFloorHide.visibleLayers` (корпуса вентиляций, скрубберов, насосов), прячутся только трубные коннекторы. Дополнительно можно указать «решётчатые» тайлы (регулярное выражение по id, по умолчанию `Lattice|Grat|Grid|Catwalk|TechMaint|Mesh`), на которых подпол тоже виден. В редакторе это включается слоем «Подпол как в игре».
- **Вессел.** Категория и группа — выпадающие списки, классы и двигатели — переключатели. Значения берутся из перечислений `VesselSize`, `ShipyardConsoleUiKey`, `VesselClass`, `VesselEngine` в C#-коде репозитория и из существующих прототипов. Калькулятор цены: оценка × (1 + наценка), наценка выбирается с шагом 5% и запоминается, есть округление и ручной ввод цены.

## Пайплайны

Кнопка «Пайплайны» запускает скрипты на JS: проверки, массовые замены, экспорт, обход многих карт.
Список берётся из папки `pipelines/` маппера (она в git: положил файл — он есть у всех, кто открывает этот
маппер). Свой `.js` можно загрузить в диалоге или перетащить в окно. Он выполняется только у вас; на сервер
его кладёт кнопка «Сохранить на сервер».

Пайплайн работает в изолированном Web Worker: без сети и доступа к файлам, с чтением сборки через API.
Правки шаттла применяются одним шагом (Ctrl+Z отменяет весь прогон), при ошибке не применяются вовсе.
Файлы результата скачиваются, а если их несколько, то одним zip. Формат и API описаны в
[pipelines/README.md](pipelines/README.md). Встроенные пайплайны: поиск ошибок, FinalView (чистовая
подготовка для DeadSpace: debug/админские прототипы, шлюзы, мелкие фиксы), замена прототипов по таблице, экспорт шаттла
с весселом (консоль и теги), прототипами, локалью и инструкцией, заготовка для обхода всех карт.

## Совместимость с форматом

- Неизвестные компоненты, поля, контейнеры и вложенные сущности сохраняются без изменений, как и порядок сущностей в группах, порядок ключей сущности и комментарии `#` перед группами прототипов.
  При копировании сущности её содержимое копируется вместе с ней, uid переназначаются.
- Сохраняются исходный порядок групп, чанков, tilemap и индексов декалей, исходные строки
  координат и углов, а также концы строк (CRLF/LF). Поэтому диффы в git остаются минимальными.
- Тест: `python tests/test_roundtrip.py [limit] [фильтр] [-v]` загружает и пересохраняет все файлы карт
  из `Maps` и `SharedMaps` (гриды, станции, формат 6 и 7); у файлов с несколькими гридами ещё раз со вторым гридом.
  Многострочные тексты (бумаги, описания) записываются блоком `>` / `>-`, как это делает движок; в кавычки
  уходят только тексты, которые блоком записать нельзя (пробелы в конце строк, табуляции). Устаревший `entityCount`
  заменяется фактическим числом сущностей, чанки старых версий (без `version`, v6) записываются как v7 — так же
  делает сам движок. Комментарии `#` внутри вложенных данных не сохраняются.
- Файлы формата 6 остаются форматом 6: шапка формата 7 к ним не добавляется, стиль компонентов
  (`type` последним ключом) сохраняется.
- Висячие ссылки на удалённые сущности (DeviceList, DeviceLinkSource/Sink, ContainerContainer)
  при сохранении вычищаются.

```
mapper.py              HTTP-сервер и API

ss14map/check.py       проверка окружения для run_mapper.bat
ss14map/yamlio.py      YAML без потерь (теги !type:, строки как есть) и dumper в стиле движка
ss14map/prototypes.py  индекс entity/tile/decal/vessel, наследование, локализация, кэш

ss14map/gridfile.py    чтение/запись грида (чанки base64, 7 байт на тайл), декали, сущности
ss14map/atmos.py       генерация GridAtmosphere, поиск утечек
pipelines/             пайплайны (JS), доступные в диалоге «Пайплайны»; API — pipelines/README.md
palettes/              свои палитры (локальные, в .gitignore)
shuttles/              «Мои шаттлы»: загруженные пользователем карты (локальные, в .gitignore)
web/                   редактор (vanilla JS + Canvas, без сборки); web/js/texts.js — бумага и названия;
                       web/js/pipelines.js и pipeline-worker.js — запуск пайплайнов и их песочница
tests/                 round-trip тест
```
